# 02 运行与部署

## 1. 环境要求

| 项目 | 要求 |
| --- | --- |
| Python | 3.10+（Termux 的 `pkg install python` 给 3.12） |
| 依赖 | 见 `requirements.txt`，8 个包全是纯 Python，无需编译 |
| 磁盘 | 代码约 1 MB，数据随记录增长（每次执行约几 KB） |
| 内存 | 常驻约 60–90 MB |
| 网络 | 能访问 `api.seiue.com`、`passport.seiue.com` |

不需要：root、编译器、Node.js、数据库服务、容器。

## 2. 安装

### 2.1 Termux / Android

```bash
pkg update -y && pkg install -y python unzip
# 把项目目录放到 ~/badminton-booker（下载 zip 后 unzip 即可）
cd ~/badminton-booker
python -m pip install -r requirements.txt
```

国内网络慢可加镜像：

```bash
python -m pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

### 2.2 Linux / macOS / Windows

```bash
cd badminton-booker
python -m venv .venv
.venv/bin/pip install -r requirements.txt        # Windows: .venv\Scripts\pip
```

## 3. 启动

```bash
python run.py
```

启动后打印：

```
  希悦自动订场  v1.0.1
  ----------------------------------------------
  本机访问    http://127.0.0.1:8080
  局域网访问  http://192.168.1.23:8080
  数据目录    /path/to/badminton-booker/data
  登录口令    未设置（局域网内任何人可访问）
  ----------------------------------------------
```

| 参数 | 作用 |
| --- | --- |
| `--host 127.0.0.1` | 只允许本机访问 |
| `--port 9000` | 换端口（被占用时默认自动 +1） |
| `--strict-port` | 端口被占用直接报错，不自动换（服务化时用） |
| `--dev` | 改代码自动重载（开发用） |
| `--log-level warning` | 降低日志噪音 |

等价于 `uvicorn app.main:app`，启动器只是多了地址探测、端口检查与提示。

## 4. 常驻运行

### 4.1 systemd（Linux / NAS）

`/etc/systemd/system/booker.service`：

```ini
[Unit]
Description=希悦自动订场
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/badminton-booker
Environment=APP_HOST=0.0.0.0
Environment=APP_PORT=8080
ExecStart=/opt/badminton-booker/.venv/bin/python run.py --strict-port
Restart=always
RestartSec=5
User=booker
Group=booker

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now booker
journalctl -u booker -f          # 看日志
```

`--strict-port` 很关键：端口被占用时**必须失败**，而不是悄悄换一个——
否则你以为在 8080，实际跑在 8081。

### 4.2 Termux 保活

```bash
pkg install -y termux-api
termux-wake-lock                 # 持有唤醒锁
```

再手动把 Termux 的电池优化设为「无限制」（系统设置 → 应用 → Termux → 电池）。

开机自启（需安装 Termux:Boot）：`~/.termux/boot/start-booker.sh`

```sh
#!/data/data/com.termux/files/usr/bin/sh
termux-wake-lock
cd ~/badminton-booker && nohup python run.py >> ~/booker.log 2>&1 &
```

```bash
chmod +x ~/.termux/boot/start-booker.sh
```

### 4.3 KernelSU 模块（手机，开机自启）

模块自带开机脚本、看门狗与网页控制台，装完重启即可，不需要 Termux 常驻。
详见 [06 模块与打包](06-模块与打包.md)。

## 5. 环境变量

写进项目根目录的 `.env` 不会自动加载；用 `export`、systemd 的 `Environment=`，
或模块里的 `/data/adb/badminton-booker/config.sh`。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `APP_HOST` | `0.0.0.0` | 监听地址 |
| `APP_PORT` | `8080` | 监听端口 |
| `DATA_DIR` | 项目内 `data/` | 数据目录 |
| `APP_PASSWORD` | 空 | 访问口令；设为非空后所有页面需先登录 |
| `APP_TZ` | `Asia/Shanghai` | 时区（影响日期与「今天」） |
| `APP_PROXY` | 空 | 出网代理；不填则直连，且**不读系统代理变量** |
| `MAX_ORDER_DAYS` | `7` | 可预约窗口天数 |
| `RETRY_SECONDS` | `600` | 窗口内失败后的重试间隔 |
| `TOKEN_REFRESH_SKEW` | `600` | 令牌剩余不足多少秒就续期 |
| `TOKEN_CHECK_SECONDS` | `300` | 后台令牌巡检间隔 |
| `HTTP_TIMEOUT` | `10` | 单次请求超时（秒） |
| `LOG_LEVEL` | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |
| `CHECK_URL` | 场地清单地址 | 会话自检用的地址 |
| `API_BASE` / `SITE_BASE` | `https://api.seiue.com` / `https://chalk-c3.seiue.com` | 站点地址 |

> 程序默认 `trust_env=False`：系统里若有 `HTTP_PROXY` 之类的变量，请求不会走它，
> 避免被本机代理劫持导致 401 或超时。确需代理时显式设 `APP_PROXY`。

## 6. 数据与备份

```
data/
├── app.db        SQLite：模板、任务、执行记录、设置（含加密后的会话）
└── secret.key    加密密钥（32 字节，urlsafe-base64）
```

备份（两者必须一起）：

```bash
tar czf booker-$(date +%F).tar.gz -C /opt/badminton-booker data
```

恢复：停服务 → 解压覆盖 `data/` → 启动。

> 只备份 `app.db` 而丢了 `secret.key`，里面保存的会话与 Cookie 就解不开了，需要重新粘贴一次。

## 7. 升级

```bash
# 1. 停服务
sudo systemctl stop booker

# 2. 覆盖代码（保留 data/ 与 .env）
unzip -o badminton-booker-1.0.1.zip -d /opt/badminton-booker

# 3. 依赖有变动时重装
/opt/badminton-booker/.venv/bin/pip install -r requirements.txt

# 4. 启动
sudo systemctl start booker
```

数据库结构变更由 `store.init_db()` 自动完成（新增列 + 老数据回填），不需要手工迁移。

## 8. 装完自检

```bash
# 1. 健康检查
curl -s http://127.0.0.1:8080/healthz
# → {"ok":true,"version":"1.0.1"}

# 2. 页面可访问
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/

# 3. 能连站点（在运行程序的机器上）
curl -s -o /dev/null -w "%{http_code}\n" https://api.seiue.com/scms/venue/order-venues
# → 401 属正常（没带令牌），能返回状态码就说明网络通
```

再到网页里：设置 → 同步场地，能列出场地就说明会话有效。

## 9. 常见部署问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 端口被占用 | 已有实例在跑 | `--port` 换端口，或先停旧进程 |
| 页面能开但同步场地 401 | 令牌过期 | 设置页重贴 cURL，或配会话 Cookie |
| 启动即退出 | 缺依赖 / 数据目录不可写 | 看终端报错；`DATA_DIR` 指向可写目录 |
| 局域网访问不了 | 只监听了 127.0.0.1 | `APP_HOST=0.0.0.0` |
| 时间不对导致提前/延后 | 主机时区错 | 设 `APP_TZ=Asia/Shanghai` 并校准系统时间 |
