# 06 令牌自动续期

> 目标：**不用每天重贴 cURL**。配置一次，程序在令牌快过期时自己换新的，长期免维护。

## 1. 为什么需要

站点签发的是 **24 小时** JWT（`exp - iat = 86400`）。过期后所有请求返回 401，程序会在执行前直接拦截——安全，但每天都得手工重贴一次，很麻烦。

## 2. 站点有两条换令牌的通道（扒前端 bundle 实测）

前端源码（`/static/js/72841.835e460b34.js` 等 chunk）里，换令牌的逻辑是一个三元判断：

```js
m = null;
function v(e) {                       // e = oAuthToken.refreshToken
  return m = m || (
    e
      ? api.post("/chalk/oauth/tokens",                    // 有 RT：走 api 域
          {grantType:"refresh_token", clientId: CLIENT_APP_CLIENT_ID,
           clientSecret: CLIENT_APP_CLIENT_SECRET, refreshToken: e})
      : axios.post(PASSPORT + "/authorize",                // 没有 RT：走 passport 域
          qs.stringify({response_type:"token", client_id: CLIENT_WEB_CLIENT_ID}),
          {withCredentials: true})                          // ← 靠 HttpOnly 会话 Cookie
  ).finally(() => { m = null });
}
```

对应的配置默认值（同样来自前端 defaults）：

| 配置 | 值 |
| --- | --- |
| `SERVER_PASSPORT` | `https://passport.seiue.com` |
| `CLIENT_WEB_CLIENT_ID` | `GpxvnjhVKt56qTmnPWH1sA` |
| `CLIENT_APP_CLIENT_ID` | `bEGAfhMhb2OZ2yARn8TBxg` |
| `CLIENT_APP_CLIENT_SECRET` | `8TCt6gW9gwvFnc` |

服务端直连实测：

| 请求 | 结果 |
| --- | --- |
| `POST https://passport.seiue.com/authorize`（无 Cookie） | **401** `{"name":"Unauthorized","message":"Login required"}` |
| 同上，响应头 | 带 `Access-Control-Allow-Credentials: true`（前端因此能跨域带 Cookie 调它） |
| `POST https://api.seiue.com/chalk/oauth/tokens`（空 refresh_token） | 500，服务端解不出 RT |

**浏览器侧实测（2026-10-17 21:00，sniff.js v3 在已登录页面执行）——通道已验证可用：**

| 请求 | 结果 |
| --- | --- |
| `POST passport.seiue.com/authorize`（`credentials: include`） | **HTTP 201** |
| 响应体 | `{"token_type":"bearer","expires_in":"86400","access_token":"eyJhbGciOiJSUzI1NiJ9..."}` |

注意 `expires_in` 是**字符串** `"86400"` 而不是数字，解析时要兼容（程序已处理）。

**本站点 Web 端走的是第二条**——因为它的 `localStorage` 里压根不保存 `refreshToken`（见第 3 节实测）。

## 3. 本站点的凭据分布（2026-10-17 实测）

在 `chalk-c3.seiue.com` 页面扫描，可以直接排除两条弯路：

| 位置 | 实际内容 | 结论 |
| --- | --- | --- |
| `document.cookie` | 只有 `_pk_id.*`、`_pk_ses.*` | Matomo 访问统计，**不是鉴权凭据** |
| `localStorage` → `persist:root` | `session.oAuthToken.{tokenType,expiresIn,accessToken,activeReflectionId}`、`session.ssoProvider=tencent_campus`、用户资料 | **只有 accessToken，没有 refreshToken** |
| `sessionStorage` | `__darkreader__wasEnabledForHost`、`__imt_handshake_page_id` | 无关（深色模式插件、埋点） |
| 跨域请求 | `Access-Control-Allow-Credentials` 为空 | 服务端**不允许带 Cookie 跨域调 `/scms`**，所以「保存 Cookie 会话」这条路不成立，必须 Bearer |

所以：

- **不要在 Cookie 里找 refresh_token，它不在那儿**；前端自己也没有。
- 「只靠 Cookie 免续期」也**不可行**：`api.seiue.com` 不接受携带凭据的跨域请求。
- 唯一该看的地方是 `passport.seiue.com` 域下那个 **HttpOnly 会话 Cookie**（JS 读不到，F12 面板能看到）。
- `persist:root` 是「JSON 字符串套 JSON 字符串」，在面板里点开几乎不可读，用 `/static/sniff.js` 的深度展开看。
- `sniff.js`（v3 起）还会直接探测一次免密换令牌通道并打印结论：**返回 201 就说明这条路通**，
  照着结论去 `passport.seiue.com` 域复制 Cookie 即可。

## 4. 怎么配置（推荐：会话 Cookie，一次搞定）

**通道一：passport 会话 Cookie（推荐，已实测可用）**

1. 浏览器打开 `https://chalk-c3.seiue.com/venues/venue-list`，确认已登录；
2. F12 → **Application → Cookies → `https://passport.seiue.com`**；
3. 把该域下的 cookie 整段复制（通常一两条，形如 `PHPSESSID=xxxxxxxx`；**不要只复制 Value**）；
4. 粘贴到「设置 → ②b 令牌自动续期 → 会话 Cookie」→ 保存；
5. 点「立即续期并校验」。

粘贴形态程序都能自动整理，不用手动改格式：

| 你复制到的样子 | 处理结果 |
| --- | --- |
| `PHPSESSID=abc123` | 原样 |
| `PHPSESSID<TAB>abc123`（面板整行复制） | 补等号 |
| `cookie: PHPSESSID=abc123` | 剥掉头名 |
| `PHPSESSID=abc; Path=/; HttpOnly`（整条 Set-Cookie） | 剔掉属性段 |
| 多条各占一行 | 用 `; ` 连接 |

> 输入框留空提交 = 清除；填了但识别不出「名=值」会明确报错，不会静默清掉已保存的值。

之后程序会在令牌剩余不足 `TOKEN_REFRESH_SKEW`（默认 600 秒）时，用这个 Cookie 免密换新令牌：

```
POST https://passport.seiue.com/authorize
Content-Type: application/x-www-form-urlencoded
Cookie: PHPSESSID=xxxxxxxx

response_type=token&client_id=GpxvnjhVKt56qTmnPWH1sA
```

服务端可能借响应**轮换会话 Cookie**（返回新的 `Set-Cookie`）。程序会自动把新值存回去，
所以你复制一次之后，即使服务端定期轮换，也不用再管。

**通道二：refresh_token（界面已移除，仅代码保留兜底）**

> 设置页不再提供 refresh_token 入口（本站点 Web 端根本取不到它）。
> 后端逻辑保留：若数据库里已存有旧值，续期时仍会作为兜底尝试。

只有在你能从浏览器里拿到真正的 RT 时才用得上（本站点通常拿不到）。保存到「②b」第二栏即可，程序会在没有会话 Cookie 时回退到它。

> ⚠️ 别把 `access_token` 当 RT 用：它一定是 `eyJ...` 开头的 JWT，程序会直接拒绝。

## 5. 程序怎么用它们

保存任一通道后，会走三重保险：

1. **启动时**换一次（剩余不足阈值时）；
2. **常驻巡检**：每 `TOKEN_CHECK_SECONDS`（默认 300 秒）检查一次；
3. **每次执行前**必查一次——哪怕巡检被系统休眠打断，跑任务之前也会先尝试续期。

换到新令牌后**不做无条件信任**，而是立刻用它拉一次场地清单（`GET /scms/venue/order-venues`）：

- 返回 2xx → 才落盘（写回 Authorization）；
- 返回 4xx/5xx 或超时 → **保留旧令牌**，记录失败原因，避免把还能用的令牌换成废令牌。

这个顺序保证了一个不变量：**落盘的令牌一定是刚被验证过能用的**。

优先级：**会话 Cookie 优先于 refresh_token**，因为前者才是站点 Web 端自己走的通道。

## 6. 安全说明

- 会话 Cookie 与 session_headers、refresh_token 一样加密落盘（标准库 HMAC-CTR + EtM；密钥 `data/secret.key`），界面只显示掩码。
- 它**等同于一串长期登录凭据**：拿到它就等于能操作你的账号。所以：
  - `data/` 目录不要放进任何同步盘或公开仓库；
  - 备份 `app.db` 时**必须连 `secret.key` 一起**，否则解不开；
  - 建议给界面设 `APP_PASSWORD`，别把 8080 直接暴露到公网。
- 程序**不保存账号密码**、不模拟 SSO 登录页、不破解验证码，走的完全是浏览器自己在用的通道。
- client 凭据是前端 bundle 里明文的公共 client，不是你个人的机密。

## 7. 排错对照表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `401 Login required` | 会话 Cookie 失效/被登出 | 重新登录后从 F12 复制新的 `passport.seiue.com` Cookie |
| `这不像 cookie：至少要有一个 名=值` | 只复制了 Value，没带 Name | 整段 `Name=Value` 复制（制表符分隔的也行） |
| `没识别出有效的 cookie` | 填了内容但里面没有「名=值」 | 检查是否复制完整；留空提交才是清除 |
| `响应里没有 access_token` | 站点结构变了 | 看「上次续期」里的原文，按第 2 节重新核对 |
| `The refresh token is invalid` | RT 填错、被截断，或已被轮换后用了旧的 | 本站点通常拿不到 RT，改用会话 Cookie |
| `the property grant_type is required` | 请求被按 JSON 解析了 | 程序已强制表单编码；手测请用 `-d` |
| 控制台有 `/chalk/classin/personal/account` 404 | 账号未绑定 ClassIn，前端探测的可选分支 | **与令牌无关**，忽略；用场地清单探测判断登录态 |
| 扫描器把 `_pk_id` / `__imt_handshake_page_id` 当成 refresh 候选 | 它们是 Matomo/友盟埋点 ID，形态像乱码 | v3 起已排除这类键；本站点本来就没有 RT |
| 续期成功但立刻 401 | 新令牌校验拦截了（会提示「已保留旧令牌」） | 通常是账号会话在服务端已被踢下线 |
| 想关掉自动续期 | — | 把对应输入框留空提交，即清除 |

## 8. 验证方式

设置页点「立即续期并校验」：

- 成功 → 绿色提示「续期成功，新令牌剩余 86399s（校验 HTTP 200）」；
- 失败 → 红色提示带服务端原文，且**令牌不会被覆盖**，原有功能不受影响。

命令行验证（把 `<COOKIE>` 换成你的会话 Cookie）：

```bash
curl -sS -X POST https://passport.seiue.com/authorize \
  -H 'Cookie: <COOKIE>' \
  -d 'response_type=token' \
  -d 'client_id=GpxvnjhVKt56qTmnPWH1sA'
```

## 9. 什么情况下还是得手动重贴

- 会话 Cookie 本身过期或被服务端吊销（改密码、管理员清会话、长期不登录）；
- 学校轮换了 OAuth client（表现为 `invalid_client`）；
- 账号被登出（Tencent Campus SSO 会话失效）。

这些都属于「凭据本身失效」，除了重新登录没有别的办法——程序会在仪表盘和记录里明确写出来，不会静默失败。
