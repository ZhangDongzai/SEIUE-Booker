# 03 依赖与部署

本程序是**单进程自托管服务**：不需要容器、不需要外部数据库、不需要反向代理。
装好依赖后在项目目录执行 `python run.py` 即可完成全部功能。

- Termux / 手机上的部署，见 [07 Termux 部署](07-Termux%20部署.md)；
- 本文覆盖：依赖清单 → 目录结构 → 环境变量 → 部署（前台 / 服务化）→ 首次配置 → 运维排错。

---

## 1. 依赖清单

**全部是纯 Python 包（`py3-none-any`），任何平台装上就能跑，无需编译器。**

| 依赖 | 版本 | 用途 |
| --- | --- | --- |
| Python | ≥3.10 | 运行时 |
| starlette | ≥0.37 | Web 框架（路由、中间件、模板、静态文件） |
| uvicorn | ≥0.30 | ASGI 服务器（h11 + asyncio，**不装 `[standard]`**） |
| jinja2 | ≥3.1 | 服务端模板 |
| python-multipart | ≥0.0.9 | 表单解析 |
| httpx | ≥0.27 | HTTP 客户端 |
| jmespath | ≥1.0 | 响应字段提取 / 成功判定 |
| itsdangerous | ≥2.2 | 登录 Cookie 签名 |
| tzdata | ≥2024.1 | IANA 时区数据（Android / Windows 不自带） |

装完共 17 个包，约 20 MB。无数据库、Redis、浏览器内核、Node.js 依赖。

### 1.1 安装

```bash
cd badminton-booker
python -m pip install -r requirements.txt
```

或在 Termux / Linux 上直接用一键脚本（会顺带做 import 与时区自检）：

```bash
bash termux-setup.sh
```

国内网络慢时换镜像：

```bash
python -m pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

### 1.2 宿主机要求

- Python 3.10 及以上；
- 可用磁盘 ≥ 100 MB（依赖约 20 MB，数据几 MB）；
- 出站网络可访问 `api.seiue.com:443` 与 `passport.seiue.com:443`（无需入站公网暴露）；
- 系统时钟开启 NTP（放号时刻依赖准确时钟，程序自身也会按站点 `Date` 头校准）。

## 3. 环境变量

全部可选。可通过环境变量直接设置，或复制 `.env.example` 为 `.env` 后由 shell 载入
（`set -a; . ./.env; set +a`）。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `APP_HOST` | `0.0.0.0` | 监听地址。只允许本机访问时设 `127.0.0.1` |
| `APP_PORT` | `8080` | 监听端口 |
| `APP_PASSWORD` | 空 | 访问口令。留空则不鉴权；内网也建议设置 |
| `APP_TZ` | `Asia/Shanghai` | 时区，与站点一致，不建议改 |
| `DATA_DIR` | 项目内 `data/` | 数据目录（`app.db` 与 `secret.key` 所在处） |
| `HTTP_TIMEOUT` | `10` | 单次请求总超时（秒） |
| `APP_PROXY` | 空 | **默认直连**（不读系统 `HTTP_PROXY`）。确实需要代理时填 `http://host:port` |
| `API_BASE` | `https://api.seiue.com` | 业务接口域名，一般不用改 |
| `SITE_BASE` | `https://chalk-c3.seiue.com` | 前端壳域名，用于时钟校准 |
| `CHECK_URL` | `{API_BASE}/scms/venue/order-venues` | 会话自检地址（带令牌 200，失效 401） |
| `MAX_ORDER_DAYS` | `7` | 站点可预约窗口天数。目标日期在窗口内立即执行，否则等窗口开启 |
| `RETRY_SECONDS` | `600` | 窗口内执行未成功后的重试间隔（秒） |
| `TOKEN_REFRESH_SKEW` | `600` | 令牌剩余不足多少秒就自动续期（与前端行为一致） |
| `TOKEN_CHECK_SECONDS` | `300` | 后台巡检令牌的间隔（秒） |
| `OAUTH_TOKEN_URL` | `{API_BASE}/chalk/oauth/tokens` | 换 token 接口，一般不用改 |
| `OAUTH_CLIENT_ID` / `OAUTH_CLIENT_SECRET` | 内置公共 client | 学校轮换 client 时用它们覆盖，不必改代码 |
| `LOG_LEVEL` | `INFO` | 日志级别 |

## 4. 部署

### 4.1 前台试跑（先确认能用）

```bash
cd badminton-booker
python run.py
```

启动后终端会打印本机与局域网访问地址、数据目录、口令状态：

```
  希悦自动订场  v1.0.0
  ----------------------------------------------
  本机访问    http://127.0.0.1:8080
  局域网访问  http://192.168.1.23:8080
  数据目录    /opt/badminton-booker/data
  登录口令    已设置
  ----------------------------------------------
```

按 `Ctrl+C` 停止。想确认服务是否健康：

```bash
curl http://127.0.0.1:8080/healthz
# {"ok":true,"version":"1.5.0"}
```

### 4.2 服务化常驻（Linux / NAS 的 systemd）

机器重启后自动拉起、异常退出自动重启——这是常驻运行最关键的一环，不要省。

**① 装依赖到独立环境**（避免污染系统 Python）：

```bash
cd /opt/badminton-booker
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

**② 建立启动脚本** `/opt/badminton-booker/start.sh`：

```bash
#!/usr/bin/env bash
cd /opt/badminton-booker
set -a
[ -f .env ] && . ./.env          # 可选：从 .env 读 APP_PASSWORD 等
set +a
exec .venv/bin/python run.py --strict-port
```

```bash
chmod +x /opt/badminton-booker/start.sh
```

> `--strict-port` 让端口被占用时直接退出（由 systemd 重试），而不是自动换端口。
> 服务化部署必须加，否则端口会悄悄漂移。

**③ 写 unit** `/etc/systemd/system/booker.service`：

```ini
[Unit]
Description=Badminton Booker
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=YOUR_USER
WorkingDirectory=/opt/badminton-booker
Environment=APP_TZ=Asia/Shanghai
Environment=APP_HOST=0.0.0.0
Environment=APP_PORT=8080
Environment=DATA_DIR=/opt/badminton-booker/data
# 口令建议写在 /opt/badminton-booker/.env 里，由 start.sh 载入
ExecStart=/opt/badminton-booker/start.sh
Restart=always
RestartSec=5
StandardOutput=append:/var/log/booker.log
StandardError=append:/var/log/booker.log

[Install]
WantedBy=multi-user.target
```

**④ 启用**：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now booker
systemctl status booker            # 应为 active (running)
journalctl -u booker -f            # 或 tail -f /var/log/booker.log
```

**关闭 NAS / 主机的系统休眠**，否则到点进程处于挂起状态会错过放号。

### 4.3 手机（Termux）

见 [07 Termux 部署](07-Termux%20部署.md)：`pkg install python` → `bash termux-setup.sh` →
`python run.py`，并用 `termux-wake-lock` + 关闭电池优化保证后台存活。

### 4.4 设置访问口令

```bash
export APP_PASSWORD='换成一个只有你知道的口令'
python run.py
```

服务化部署写进 `.env`：

```
APP_PORT=8080
APP_PASSWORD=换成一个只有你知道的口令
```

口令只影响网页登录（Cookie 有效期 7 天），不影响自动预约的执行。

## 5. 首次配置流程（4 步）

1. **一键导入**：浏览器成功预约一次 → F12 → Network → 找 `order-venues/…/orders` 的 **POST** → 右键 *Copy → Copy as cURL (bash)* → 设置页「① 一键导入」粘贴 → 解析。
   完成后会话里有 Bearer 令牌，模板库里出现一份带占位符的下单模板。看到「令牌剩余有效 N 小时」即成功。
2. **同步场地**：设置页点「同步场地」，应列出 6 块羽毛球场地（带「需审批」标记）。
3. **建任务**：勾选场地（可多块，按勾选顺序尝试）、**选一个预约日期**、时段 `17:30`–`18:30`、人数、备注。
   下单模板会默认选中已导入的那份；先勾「演练模式」跑一次，确认候选场地与日期正确且没有发出 POST。
4. **转正**：取消演练，保存。日期在 7 天窗口内会**立即执行**；超出窗口则等到窗口开启那天自动开始。
   约到后任务自动停用；没约到会按 `RETRY_SECONDS` 重试，直到成功或日期过去。

> 令牌 24 小时过期。配了「设置 → ②b 会话 Cookie」就会自动免密续期，不必每天重贴；
> 不配则每天重复第 1 步（其余配置不用动）。见 [06 令牌自动续期](06-令牌自动续期.md)。

## 6. 运维

| 事项 | 操作 |
| --- | --- |
| 查看日志 | 前台运行直接看终端；systemd 用 `journalctl -u booker -f` 或 `tail -f /var/log/booker.log` |
| 重启 | `sudo systemctl restart booker` |
| 停止 | `sudo systemctl stop booker`（数据保留在 `data/`） |
| 升级 | 覆盖代码目录（保留 `data/`）→ `.venv/bin/pip install -r requirements.txt` → `systemctl restart booker`。老库会自动补列，数据不丢 |
| 备份 | 打包 `data/`；`app.db` 与 `secret.key` **必须一起备份**，否则已存会话无法解密 |
| 迁移 | 整目录搬到新机器（含 `data/`），重装依赖后启动即可 |
| 健康检查 | `curl -s http://127.0.0.1:8080/healthz` |
| 更新令牌 | 配了会话 Cookie 则无需人工干预；否则设置页重贴一次 POST cURL |
| 清理记录 | 「记录」页可删除单条轮次；长期运行建议保留 30 天 |

### 6.1 定时任务的稳定性前提

- **关闭主机休眠**：到点进程必须处于运行状态。systemd 部署也救不了休眠。
- **时钟准确**：开启 NTP。程序会按站点 `Date` 头校准偏移，但系统时间跳变会打乱倒计时。
- **链路可用**：确认运行主机与校园网之间在放号时刻可达（校园网若需 VPN，
  要在主机层建立连接；程序本身不会登录 VPN 客户端）。
- **不要用 `--host 127.0.0.1` 后又指望局域网访问**：两者互斥。
- 默认**直连**、不读系统代理；若出口必须过代理，设置 `APP_PROXY`。

### 6.2 备份与恢复

```bash
# 备份（建议加进 cron，每天一次）
tar czf ~/booker-$(date +%F).tar.gz -C /opt/badminton-booker data

# 恢复
tar xzf booker-2026-10-17.tar.gz -C /opt/badminton-booker
sudo systemctl restart booker
```

`data/` 里只有两个文件：`app.db`（任务、模板、记录）与 `secret.key`（加密密钥）。
换机器时**两个都要带**，否则已保存的会话与 Cookie 全部作废，需要重新粘贴。

### 6.3 常见故障

| 现象 | 排查 |
| --- | --- |
| 启动即退出，提示端口被占用 | `ss -lntp \| grep 8080` 找占用进程；或 `--port` 换一个 |
| 页面打不开 | 确认监听地址（`--host 0.0.0.0` 才允许局域网）；检查防火墙是否放行端口 |
| `ModuleNotFoundError: starlette` | 依赖没装到当前解释器：用启动脚本里那个 `.venv/bin/python` 装 |
| `data` 目录无写权限 | `chown -R $(id -u):$(id -g) data` |
| 仪表盘红旗「令牌过期」 | 按第 5 节第 1 步重新导入，或配好「②b 会话 Cookie」 |
| 会话自检返回 401 | 令牌失效；403 则是缺 `x-school-id`/`x-role`，用一键导入重抓 |
| 同步场地为空 | 会话无效，或 `API_BASE` 被改错 |
| 抢点总是晚 1~2 秒 | 看仪表盘的「站点时钟偏移」；确认主机已开启 NTP 自动校时 |
| 请求一直 HTTP 0 | 出网被拦：在运行终端里 `curl -I https://api.seiue.com`，必要时配 `APP_PROXY` |
| 提交成功但没预约 | 场地需审批，到「我的预约」审批 |
| 息屏 / 锁屏后任务没执行 | 手机端保活没做，见 07 文档第 7 节 |
| `Temporary failure in name resolution` | 主机 DNS 不通：`cat /etc/resolv.conf`，换成 `223.5.5.5` |
