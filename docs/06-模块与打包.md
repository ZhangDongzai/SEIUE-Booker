# 06 模块与打包

KernelSU 模块把程序装进 `/data/adb/modules/`，由 root 在开机时拉起，
并提供一个网页控制台。适合「手机常驻、不想开 Termux」的场景。

## 1. 它做了什么

| 能力 | 实现 |
| --- | --- |
| 开机自启 | `service.sh` 等 `sys.boot_completed=1` 后拉起服务 |
| 状态展示 | 每 20 秒写 `webroot/status.json`，同时把状态写回 `module.prop` 的 `description` |
| 网页控制台 | `webroot/index.html`，可启动/停止/自检/看日志/内嵌完整界面 |
| 自动恢复 | 心跳里每 60 秒健康检查一次，连续 3 次不通就重启 |
| 卸载清理 | `uninstall.sh` 先停心跳再停进程，数据目录保留 |

## 2. 目录结构

```
kernelsu-module/
├── module.prop          模块信息（id/name/version/author/description）
├── service.sh           开机自启 + 心跳 + 看门狗
├── post-fs-data.sh      早期初始化：建目录、记录模块真实路径
├── customize.sh         安装时：设权限、检查 Python、打印路径
├── uninstall.sh         卸载时：停心跳与进程（数据保留）
├── ctl.sh               控制脚本：start/stop/restart/status/probe/watchdog/
│                        diag/selfcheck/deps/install-deps/log/where
└── webroot/
    ├── index.html       控制台
    └── status.json      运行时由 ctl.sh 写入的状态快照
```

安装后：

```
/data/adb/modules/badminton_booker/      模块本体（含 app/ 程序副本）
/data/adb/badminton-booker/
├── data/app.db + secret.key             数据（与 Termux 方式分开）
├── booker.log                           程序日志
├── service.log                          开机与心跳日志
├── module_path                          模块真实目录（控制台靠它定位 ctl.sh）
├── booker.pid / heartbeat.pid           进程号
└── config.sh                            可选：覆盖端口等配置
```

## 3. 安装与首次使用

**前置**：Termux 里装好 Python（模块复用它的运行时，不额外打包解释器）。

```bash
pkg install python
```

**步骤**：

1. 把 `dist/badminton-booker-ksu-v1.0.1.zip` 传到手机；
2. KernelSU 管理器 → 模块 → 从本地安装 → 选择该 zip；
3. 重启手机（模块需要在开机时执行脚本）；
4. 打开该模块的网页控制台：
   - 若提示缺依赖，点「安装依赖」；
   - 点「启动」，状态变成 `运行中`；
   - 点「在本页打开界面」直接进入完整配置，或点「用浏览器打开」。

> 模块列表里显示的 `运行中[PID: 18197]` 是 `description` 字段，由程序实时改写；
> 停止时变回 `已停止`。

## 4. 可选配置

新建 `/data/adb/badminton-booker/config.sh`（会被 `ctl.sh` source）：

```sh
HOST=0.0.0.0                 # 只让本机访问就写 127.0.0.1
PORT=8080
# 想与 Termux 方式共用数据：
# DATA_DIR=/data/data/com.termux/files/home/badminton-booker/data
```

改完在控制台点「重启」。

## 5. 控制台的命令通道

KernelSU 通过 `ksu.exec` 让网页执行 root 命令。官方契约（见 npm 包 `kernelsu`）：

```js
window[callbackName] = (errno, stdout, stderr) => { /* ... */ };
ksu.exec(command, JSON.stringify(options), callbackName);
```

**第三参数是「函数名字符串」，不是函数对象**；`options` 也必须是字符串。
传对象会抛 `Java exception was raised`，传函数则永远不会回调（表现为超时）。

`spawn` 同理，四参数：

```js
window[childName] = child;   // child 需要 stdout/stderr 的 on/emit
ksu.spawn(command, JSON.stringify(args), JSON.stringify(options), childName);
```

控制台按官方契约实现，并保留几种历史写法作为兜底，用 `echo __KSU_OK__` 并发探测后择优，
结果记在 `localStorage`，下次直接用。

**为什么状态不依赖它**：控制台优先 `fetch('status.json')`——一次静态文件请求，
不需要 root、也不会超时。只有「启动/停止」这类动作才走命令通道。
两条通道任意一条通，页面就能正常用。

## 6. 自愈

```
service.sh
  └─ 心跳（每 20s）
       ├─ ctl.sh status    刷新 status.json + 改写 module.prop 的 description
       └─ 每 3 次（60s）
            └─ ctl.sh watchdog
                 进程在 + /healthz 200          → 什么也不做
                 进程在 + 连续 3 次不通（3 分钟） → stop + start
                 进程不在                       → 什么也不做（等用户点启动）
```

程序侧还有一道：`main._loop_monitor` 每 2 秒测事件循环漂移，
超过 5 秒就把所有线程栈打进 `booker.log`，方便定位「页面一直转圈」。

## 7. 打包

```bash
python build-module.py                # → dist/badminton-booker-ksu-v1.0.1.zip
python build-module.py --out /tmp     # 换输出目录
python build-module.py --version v1.0.2   # 只改包名版本（不动文件）
python build-module.py --verify-only  # 只校验 dist 里最新的包
```

脚本做的事：

1. 读 `module.prop` 取版本号；
2. 把模块脚本与 `app/` 程序副本铺到临时目录（排除 `__pycache__`）；
3. `.sh` / `.prop` / `.html` 强制转成 **LF**（CRLF 会让 Android 上的 `sh` 报 `\r: not found`）；
4. 压缩成 zip（`module.prop` 与 `webroot` 必须在 zip 根目录）；
5. 校验：必备文件齐全、无缓存、换行正确、`id` 未被改动。

只依赖标准库，Windows / Linux / macOS 都能跑。

## 8. 排错

先在控制台点「**环境自检**」，它一次输出：命令通道形态、uid、`/data/adb/modules` 列表、
`module_path`、`ctl.sh` 候选、`webroot` 内容。绝大多数问题看这一屏就能定位。

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 模块列表显示「已停止」但服务在跑 | 心跳没起来 | 看 `service.log`；重启手机 |
| 控制台写「命令通道不可用」 | `ksu.exec` 契约不匹配 | 状态仍能看；启停临时用下面的命令 |
| 控制台写「读取失败」 | 快照与命令都拿不到 | 检查模块是否启用、`module_path` 是否存在 |
| 运行时显示「缺 Python」 | Termux 未安装 / PATH 不对 | `pkg install python`，再点「安装依赖」 |
| 点启动立刻变回停止 | 缺依赖或端口被占 | 看「运行日志」末尾几行 |
| 健康检查非 200 但进程在 | 端口被别的实例占用 | 改 `config.sh` 的 `PORT` 后重启 |
| 开机没自动启动 | 模块未启用 / 脚本未执行 | 确认 KernelSU 里是启用状态，重启 |

命令行等价操作：

```bash
su
cat /data/adb/badminton-booker/module_path        # 模块真实目录
sh "$(cat /data/adb/badminton-booker/module_path)/ctl.sh" status
sh "$(cat /data/adb/badminton-booker/module_path)/ctl.sh" diag
sh "$(cat /data/adb/badminton-booker/module_path)/ctl.sh" start
```

## 9. 备份与卸载

```bash
# 备份（只要 data 目录）
su -c 'tar czf /sdcard/booker-$(date +%F).tar.gz -C /data/adb/badminton-booker data'
```

- **卸载模块**：KernelSU 管理器里删除即可，进程与心跳会先被停掉，数据目录**保留**；
- **彻底清理**：`su -c 'rm -rf /data/adb/badminton-booker'`（`secret.key` 一并删除，
  之前保存的会话将无法解密）。
