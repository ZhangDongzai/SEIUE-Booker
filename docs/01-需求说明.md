# 01 需求说明

## 1. 背景与目标

校园羽毛球场（`https://chalk-c3.seiue.com/venues/venue-list`，希悦教学管理系统）采用「先到先得」的在线预约制，场地紧俏时需要在放号瞬间手动点选，人工操作难以稳定命中。

本项目是一个**自托管的自动预约工具**：在自己可控的主机（Linux 服务器、NAS 或手机）上常驻运行，提供网页界面，提前配置好「目标场地 + 目标时段 + 预约日期」，在放号时刻自动按真实预约接口的语义提交请求，并把每一次请求与响应完整留痕。

设计原则：

1. **不猜接口**。程序不硬编码任何预约接口地址与字段，全部由使用者从浏览器「复制为 cURL」导入后配置，接口变动只需改配置、无需改代码。
2. **可解释**。每次执行都留下「渲染后的请求 + 原始响应」，失败原因可自查，不做黑盒重试。
3. **有边界**。只辅助自己账号的预约，不做验证码破解、不做多账号代理池、不做绕过风控的频率轰炸。

## 2. 名词定义

| 术语 | 含义 |
| --- | --- |
| 放号时刻 | 系统允许提交某一天预约的最早时间点，本项目按 `Asia/Shanghai` 精确对齐 |
| 预约日期 `target_date` | 任务的目标日期，用户直接选具体某天（如 `2026-10-21`）。站点可预约未来 7 天，超出窗口的日期会在窗口开启时自动执行 |
| 模板 | 从 cURL 解析出来的一个请求定义：方法、URL、请求头、请求体，含 `{{占位符}}` |
| 列表模板 | 「查询某天有哪些场地/时段可约」的请求，用于在放号前解析出真实 ID |
| 下单模板 | 「提交预约」的请求，用于真正下单 |
| 轮次 run | 一次调度触发（定时或手动）产生的完整执行记录 |
| 尝试 attempt | 轮次内的一次 HTTP 请求（含重试） |
| 已提交 | HTTP 2xx（或自定义成功表达式为真）。系统若存在审批流，已提交 ≠ 审批通过，本项目只负责提交 |

## 3. 功能需求

### FR-1 会话管理
- 支持粘贴浏览器中「提交预约」那条请求的 cURL（或纯 `Key: Value` 头文本）导入会话，自动提取 `Authorization: Bearer …`、`Cookie`、`x-role`、`x-school-id`、`User-Agent` 等身份与上下文头。
- 会话加密落盘（标准库 HMAC-CTR + Encrypt-then-MAC，密钥自动生成在数据目录），界面只显示掩码，不回显明文。
- 解析 JWT 的 `exp`，在仪表盘与设置页显示剩余有效期；**不足 3 小时黄条告警，已过期红条告警并在执行前直接拦截**。
- 提供「会话自检」：向场地清单接口发一次 GET，200 为有效、401 为失效。
- 支持随时覆盖更新（重新登录后粘贴新的 cURL 即可）。

### FR-2 模板库
- 新建 / 编辑 / 删除模板，区分 `list`（查询，可选）与 `order`（下单，必需）两类。
  首次启动**只预置场地清单模板**；下单模板不预置，必须由「一键导入」从真实 cURL 生成。
- 粘贴 cURL 一键解析：支持 `-X`、`-H/--header`、`--data-raw`、`--data`、`--data-binary`、`-b/--cookie`、`--compressed`、多行 `\` 续行、Chrome 复制出的伪头（`:authority` 等自动忽略）。
- **一键导入（quickstart）**：粘贴一条真实 POST cURL 后自动完成三件事——身份头存入会话、URL 中的场地 ID 替换为 `{{venue_order_id}}`、请求体中的日期/时段/人数/备注替换为占位符。
- 提供「探测」按钮：用示例上下文真实发送一次只读请求，把响应 JSON 以可折叠结构展示，辅助确认字段名。
- 模板支持占位符渲染，变量表见 §5。

### FR-3 目标配置（任务）
- 一条任务 = 一个预约意图，包含：
  - **任务名称由系统生成**，格式为「目标日期 + 时段」（如 `2026-10-21 17:30-18:00`），用户不填
  - 目标场地：从同步下来的场地清单里勾选（可多选），**按勾选顺序**依次尝试，失败自动换下一块
  - 目标时段（开始 / 结束，如 `17:30` / `18:30`），**整段提交**，不做拆分
  - 目标日期（具体某天，`YYYY-MM-DD`）。已在 7 天窗口内 → 立即执行；未进窗口 → 等到窗口开启那天自动执行
  - 使用人数 `capacity`、备注 `description`
  - 窗口开启时刻 `open_time`（默认 `00:00:30`）：仅对"还没进窗口"的任务生效，到那一天这个点开始尝试
  - 下单模板绑定；场地清单模板可选（仅用于补充「是否需要审批」等元信息）
  - 成功判定：`http2xx` 或自定义表达式（JMESPath）
  - 重试：轮数、间隔、预热提前量
  - 演练模式（`dry_run`）：只列出将尝试的场地、不提交下单请求
- 任务可启用 / 停用，可手动「立即执行一次」。

### FR-4 调度与执行
- 常驻调度器为每个启用任务维持一个独立协程，循环重算「下一次该执行的时刻」：
  目标日期已在窗口内 → 立即执行；未进窗口 → 等到窗口开启日；执行未成功则按 `RETRY_SECONDS`（默认 600s）重试。
- 预约成功即自动停用该任务（目标日期只有一天，不必重复预约）；目标日期过去后任务自然失效。
- 精度：目标 ±50ms 级对齐；到点前 `prewarm_ms`（默认 8000ms）先把连接预热，并在放号前 200ms 精细轮询等待。
- 时钟校准：启动时与每 10 分钟读取站点响应的 `Date` 头，计算本机与站点的时钟偏移，调度按站点时间对齐。实测这台开发机比站点慢 7.5 秒，不做校准会稳定抢晚。
- 执行顺序：检查令牌有效期 → 按勾选顺序遍历场地 → 渲染下单模板并提交 → 判定成功 → 成功即停。
- 失败处理：单块场地失败立即换下一块；全部失败则按 `interval_ms` 间隔进入下一轮，直到 `max_attempts` 用尽或超过硬性时限（120s）。
- 幂等保护：一旦判定成功立即终止后续尝试，避免重复下单；同一任务同一时刻不会并发执行两次（进程内互斥锁）。

### FR-5 记录与审计
- 轮次列表：任务、触发方式、计划时刻、开始/结束、结果、消息。
- 轮次详情：每次尝试的方法、URL、渲染后的请求头/请求体、HTTP 状态码、耗时、响应摘要（截断 8KB）、异常信息。
- 仪表盘：下次执行倒计时、今日结果统计、会话状态、站点时钟偏移。

### FR-6 部署形态
- 单进程运行（`python run.py`），仅依赖 SQLite 与本机时钟，不依赖外部数据库 / Redis / 消息队列。
- 不依赖容器、反向代理或任何外部服务；装好纯 Python 依赖即可运行。
- 数据全部落在项目内的 `data/` 目录，升级代码不丢配置与记录。
- 支持 Termux（Android）与常见 Linux / macOS / Windows；宿主机需能访问校园站点。
- 可选访问口令（环境变量 `APP_PASSWORD`），未设置时不做鉴权，适合内网环境。

## 4. 非功能需求

| 项 | 要求 |
| --- | --- |
| 时间精度 | 放号时刻对齐误差 ≤ 50ms（不含网络 RTT） |
| 资源占用 | 常驻内存 < 200MB，CPU 空闲时接近 0 |
| 启动速度 | 冷启动 < 3s 可用 |
| 时区 | 固定 `Asia/Shanghai`，与站点一致 |
| 可观测 | 标准输出结构化日志 + 页面内记录 |
| 安全 | 会话加密存储、页面掩码、可选口令、不落盘明文密码 |
| 兼容性 | Python 3.12 镜像；不依赖浏览器与 GPU |

## 5. 模板变量表

渲染上下文（下单模板与列表模板共用）：

| 占位符 | 示例 | 说明 |
| --- | --- | --- |
| `{{date}}` | `2026-10-24` | 目标日期 |
| `{{date_compact}}` | `20261024` | 紧凑日期 |
| `{{date_slash}}` | `2026/10/24` | 斜杠日期 |
| `{{date_cn}}` | `2026年10月24日` | 中文日期 |
| `{{weekday}}` | `6` | 星期（1=周一） |
| `{{weekday_cn}}` | `周六` | 中文星期 |
| `{{slot_start}}` | `19:00` | 时段开始 |
| `{{slot_end}}` | `20:00` | 时段结束 |
| `{{slot_start_full}}` | `19:00:00` | 带秒 |
| `{{slot_end_full}}` | `20:00:00` | 带秒 |
| `{{datetime_start}}` | `2026-10-24 17:30:00` | 完整开始时间 |
| `{{datetime_end}}` | `2026-10-24 18:30:00` | 完整结束时间 |
| `{{date_ranges}}` | `{"start_at":"2026-10-24","end_at":"2026-10-24"}` | **裸 JSON**，直接注入 `date_ranges` |
| `{{time_ranges}}` | `[{"start_at":"…","end_at":"…"}]` | **裸 JSON 数组**，按整段时段生成 |
| `{{order_type}}` | `single_day` | 下单类型（固定值，界面不暴露） |
| `{{capacity}}` | `2` | 使用人数（数字） |
| `{{description}}` | `打球` | 备注 |
| `{{venue_order_id}}` | `2953` | 当前候选的场地 ID（用在下单 URL 路径里） |
| `{{venue_name}}` | `羽毛球场地13号` | 当前候选场地名 |
| `{{venue_id}}` | `2953` | 同 `venue_order_id` 的别名 |
| `{{slot_id}}` | `8848` | 列表解析出的时段 ID（站点当前无此数据，通常为空） |
| `{{venue_num}}` | `1` | 场地序号（若列表提供） |
| `{{ts}}` | `1792228675` | 秒级时间戳 |
| `{{ts_ms}}` | `1792228675000` | 毫秒时间戳 |
| `{{uuid}}` | `3f2a...` | 随机 UUID4 |
| `{{nonce}}` | `a1b2c3d4e5f6` | 12 位随机十六进制 |
| `{{rerun}}` | `1` | 第几轮（从 1 开始） |

规则：

- 出现在 JSON 请求体中、且整段被引号包裹的占位符（`"{{capacity}}"`）会**按变量原始类型**替换：变量是数字则输出 `2`，是字符串则输出 `"2"`。避免「接口要数字却传了字符串」的常见坑。
- `{{date_ranges}}` / `{{time_ranges}}` 必须**裸写**（不加引号），它们渲染成对象/数组字面量。
- 请求头同样支持占位符。
- 未定义的占位符渲染为空串，并在执行记录里标注告警，不静默失败。
- 身份类头（`Authorization`、`Cookie`）以导入的会话为准，模板里的同名字头不会覆盖它——换令牌只需重新导入一次，不必改模板。

## 6. 明确不做的部分

- 自动登录 / 自动过 SSO / 自动过验证码（会话由使用者从浏览器导入）。
- JWT 自动续期（站点令牌 24 小时，需人工重新导入或另行对接 SSO）。
- 多账号、代理池、并发轰炸、绕过站点频率限制。
- 代抢、转卖等任何形式的第三方获利使用。
- 审批流推进：本站点场地 `need_approval = true`，程序只负责提交成功，**审批需本人在「我的预约」里完成**。

## 7. 已确认事实（2026-10-17 实测）

| 项 | 结论 |
| --- | --- |
| 数据面域名 | `https://api.seiue.com`（前端壳是 `chalk-c3.seiue.com`） |
| 场地清单 | `GET /scms/venue/order-venues` 返回全部 14 个场地，其中羽毛球 6 块，ID `2948`–`2953` |
| 下单 | `POST /scms/venue/order-venues/{场地ID}/orders`，请求体 5 个字段 |
| 鉴权 | `Authorization: Bearer <JWT>` + `x-role` / `x-school-id` / `x-reflection-id` |
| 令牌有效期 | 24 小时（`exp - iat = 86400`），过期即 401 |
| 预约窗口 | `max_order_days = 7`，即最多提前 7 天 |
| 审批 | 6 块羽毛球场地全部 `need_approval = true` |
| 单人限额 | `time_limit = 1`（小时级上限，具体语义按站点实际） |
| 放号时刻 | **仍未确认**，默认 `00:00:30`，请在界面按实际观察修改 |
| 时段可用性接口 | 未找到（`GET …/orders` 405，其它猜测路径 404），故程序不做时段探测，直接提交 + 重试 |
| 场地开放时间 | 工作日 `16:35–18:30`（`open_time_ranges`），时段填写超出该区间大概率被拒 |

## 8. 验收标准

1. `python run.py` 后访问 `http://127.0.0.1:8080` 能打开界面，`/healthz` 返回 `{"ok":true}`。
2. 在设置页粘贴一条真实 POST cURL，点「解析并生成配置」后：会话有了 Bearer 令牌、模板页出现带 `{{venue_order_id}}` 的下单模板。
3. 「同步场地」能列出 6 块羽毛球场地（含「需审批」标记）。
4. 勾选场地、填 `17:30–18:30`、开启演练并手动执行：记录里能看到将依次尝试的场地，且没有任何 POST 发出。
5. 关闭演练、手动执行：记录里能看到真实下单请求（URL 带正确场地 ID、请求体 5 字段正确），状态判定符合实际响应。
6. 把 `open_time` 设为 2 分钟后，调度器在该时刻自动触发（`planned_at` 与 `started_at` 差值 < 50ms）。
7. 令牌过期后执行：直接判失败并提示重新导入，不发任何网络请求。
8. 重启进程 / 主机后，任务、模板、历史记录、会话全部保留。
